# Alexandria: Unity → Godot migration plan

Moving the game from Unity 6 (URP 2D) to **Godot 4.7** (2D, isometric). This repo ([alexandria-godot](https://github.com/masterpreenz/alexandria-godot)) is the Godot project. The Unity project stays in its own repo, untouched and runnable, as the reference until this version matches it. On this machine the Godot project is checked out inside the Unity one, at `My project/godot/` (the Unity repo ignores that folder), so the exporter there can write straight into it.

## Decisions

| Question | Choice | Why |
|---|---|---|
| Language | **GDScript** | The installed Godot (4.7.2 standard) has no .NET. GDScript is Godot's first-class language, with the best editor and tooling support. Almost none of the C# would survive as-is anyway: nearly every line touches Unity's API. |
| Units | **1 Unity unit = 128 px**. A ground cell (1 × 0.5 units) is a **128 × 64 px** diamond. | Matches the 2:1 isometric grid exactly. Godot's y axis points down, so Godot `(x, y)` = Unity `(x·128, −y·128)`. |
| Draw order | **Y-sort**: every world sprite's node sits at its *sort point*, with its art offset from there. | Unity sorted by `sortingOrder ≈ −y·100`, plus hand-made offsets for walls and roofs. Putting each node's y where its sort order says reproduces Unity's order exactly, and moving actors (Miko, villagers, monsters) sort by their feet on their own. |
| World data | **Exported from Unity, not rebuilt by hand.** An exporter in the Unity project writes everything that makes up the world to JSON (`data/` here); Godot loads it. | 3,000 placed sprites, 80,000 ground cells and the river and pond meshes would take weeks to re-place. The exporter can be re-run whenever the Unity world changes. |
| Art | **Copied as-is** into `assets/`, mirroring Unity's `Assets/` (so `Assets/Art/…` becomes `res://assets/Art/…`). Each image's Unity import settings (pixels per unit, pivot, sheet slices) go into a manifest. | Git LFS stores identical files once, so the copies cost no extra space. |
| Saves | **New save format** in Godot, with the **same sections** (`world.floors`, `village.people`, …). An importer for Unity saves can come later if wanted. | The Unity saves are sealed with AES/HMAC keyed to Unity. |
| Renderer | **Forward+**, 2D lights (`PointLight2D` and `CanvasModulate` for day and night). | Covers what URP 2D Lights did. |

## Phases

Each phase ends with something playable in Godot, checked against the Unity build.

### Phase 0: Groundwork *(started)*
- The Godot project (this repo): 2D, isometric units, Forward+, linear filtering, a 1600×900 window that scales.
- Folder layout: `assets/` (mirrors Unity's `Assets/`), `data/` (exported JSON), `scenes/`, `scripts/`; `shaders/` and `audio/` as they're ported.
- **Unity exporter** (`Assets/Editor/GodotExport.cs`, menu *Tools ▸ Export to Godot*). It writes:
  - `data/sprites.json`: every sprite used (image, slice rectangle, pivot, pixels per unit).
  - `data/world.json`: every ground and floor tile, every placed sprite (trees, rocks, props, walls, roofs, decorations) with its position, flip, scale, colour and sort point, and the water meshes.
  - It also copies the art it uses into `assets/`.
- **World viewer** in Godot: loads the export and draws the whole world (ground, floors, everything placed, water), with a camera you can pan and zoom. This is the first look at the world in Godot.

### Phase 1: Walking around
- Miko: movement in 8 directions on the iso grid, her animations (sheets sliced from the manifest), collisions with trees, rocks, walls and water.
- Camera follow, zoom, and the map's edge.
- Y-sorting between Miko and the world (trees fading when she's behind them, the outline).
- Day and night lighting, `CanvasModulate` plus lights for fires and crystals.

### Phase 2: World systems
- Grid maps as live systems instead of a snapshot: **FloorMap** (dual-grid painting), **WallMap** (walls and doors), **PropMap**, **RoofMap** (roofs, see-through when inside, chimneys).
- Water: the river, ponds, lakes and waterfall, with their shaders ported.
- Mist (shader, tiers, clearing), cleansing crystals with their barriers, teleport crystals.
- Weather, snow, wind, sky effects, the game clock, seasons.
- World chunks (switching far areas off), so a 284 × 284 world runs smoothly.

### Phase 3: Gameplay
- Gathering (trees, rocks, felling, logs), pickups, the inventory and bag, the hotbar.
- Combat: damage, the HP bar, spells and casting, shikigami, monsters (slimes, boars), rabbits.
- Player needs, fainting, sleeping, beds, fires, cooking, farming and crops, food buffs, potions, workbenches and crafting.
- Corruption, mist flora, springs, healthy-forest wildlife.

### Phase 4: The village
- Villagers (the biggest script): jobs, needs, schedule, pathfinding, emotes and chat, recruitment.
- Village growth, construction and blueprints, storage, keep-in-stock targets, the jobs window.

### Phase 5: UI
- HUD, character panel, talent web, build mode and build bar, world map and minimap, chest and workbench windows, save menu.
- Godot `Control` nodes with a shared theme, ported from UiKit and UiTheme.

### Phase 6: Saves, polish, switch-over
- Save system with the same sections, autosave, slots.
- Sound, particles (puffs, sparks, motes), level-up effects.
- Side-by-side check against Unity, then the Godot build becomes the game. The Unity project is archived and stays in git history.

## Mapping Unity → Godot

| Unity | Godot |
|---|---|
| `MonoBehaviour` | Script on a `Node2D` (or a `Node`) |
| `ScriptableObject` | `Resource` (`.tres`) |
| Prefab | Packed scene (`.tscn`) |
| `SpriteRenderer` | `Sprite2D` (`centered = false`, `offset` from the pivot) |
| `Tilemap` (isometric) | `TileMapLayer` (isometric, 128×64), or drawn chunks for the dual-grid floors |
| `sortingOrder` | Y-sort (sort point = node position) |
| `Light2D` (URP) | `PointLight2D`; `CanvasModulate` for the global light |
| `ParticleSystem` | `GPUParticles2D` / `CPUParticles2D` |
| `Rigidbody2D` + colliders | `CharacterBody2D` / `StaticBody2D` + `CollisionShape2D` |
| `[RuntimeInitializeOnLoadMethod]` statics | Autoload singletons |
| `Physics2D.OverlapCircleAll` | `PhysicsDirectSpaceState2D.intersect_shape` |
| UI (`Canvas` / `Image` / `Text`) | `Control` / `TextureRect` / `Label` |

## Tooling

**Godot MCP Toolkit** (NPGameDev, v1.1.2) is the MCP used for this port. It replaces the earlier `godot-mcp` (Coding-Solo), which has been removed from the Claude Code config.

| | Godot MCP Toolkit (now) | godot-mcp (before) |
|---|---|---|
| How it works | An editor plugin (`addons/godot_mcp_toolkit`) runs a localhost server inside the open Godot editor. An npm bridge (`@npgamedev/godot-mcp-server`) connects Claude Code to it. | A standalone Node server that runs the Godot command line. |
| Scripts | Read, write and edit, with a compile check and diagnostics (`script_write`, `script_edit`, `script_check`), plus code navigation through Godot's language server (`lsp_*`). | None. |
| Scenes and nodes | The live editor's scene tree: create and delete nodes, set properties, signals, instancing, with undo. | Create a scene, add a node, load a sprite, save. |
| 2D content | TileMaps and TileSets, SpriteFrames, animations and AnimationTrees, particles, themes, input map, audio buses. | Nothing beyond sprites. |
| Running the game | Start and stop playtests, read the runtime log, simulate input, inspect and change the running game, run code in it (`execute_code`), screenshots, breakpoints. | Run and read debug output. |
| Needs | The Godot editor open on the project, with the plugin enabled (it is: see `project.godot`). Node 22+. | Just the Godot binary. |

Setup in this repo:
- `.mcp.json` at the Unity project's root starts the bridge with `GODOT_MCP_PROJECT_PATH` pointing at this project (`My project/godot`), so it works from a Claude Code session opened on the Unity project.
- Claude Code asks once to approve the project's MCP server. It loads in the next session.
- The runtime half (`MCPRuntimeServer` autoload) lets the toolkit look inside a running game. The plugin strips it from exported builds.

Without the editor open, Godot can still be run directly: `Godot_v4.7.2-stable_win64_console.exe --path godot` (the world viewer also takes `-- --shot=file.png` to save a screenshot).
